*(تشمل هذه الفئة **5 مشاكل** تتعلق بترتيب العناصر البصري وتضارب ملفات التنسيق وتوحيد الشكل العام.)*

#### `AUDIT-035` — تضارب 3 أنظمة تصميم مع بعضها (`Bootstrap 5` + `theme.css` + `Tailwind CSS`)
- **حالة التحقق:** مؤكدة (Verified) — **الأدلة:** `screenshots/38-manager-done-request-rtl-bug-1366.png` + فحص الـ CSS المحسوب (`Computed Styles`).
1. **اسم المشكلة:** صراع وتضارب ثلاثي في أنظمة التصميم (`Bootstrap 5` مع `theme.css` مع `Tailwind v3`).
2. **درجة الخطورة:** متوسطة (Medium).
3. **المكان:** `resources/js/app.jsx` (السطور 1–5)، `resources/css/theme.css` (السطر 56)، `package.json` (السطور 13، 22، 27)، وصفحة `DoneRequest.jsx` (السطور 327–357).
4. **إيه المشكلة؟** المشروع محمّل **Tailwind v3** الأول، وبعده ملف عام اسمه `theme.css` كاتب قاعدة خطيرة هي `.btn { width: 100%; border-radius: 25px; }` (يعني أي عنصر عليه كلاس `btn` ياخد عرض 100% من الشاشة!)، وبعده محمّل **Bootstrap 5** بخصائص `!important` (أولوية قصوى تجبر المتصفح ينفذها غصبًا عن Tailwind). وفوق كل ده في `package.json` حزمة `@tailwindcss/vite` (إصدار 4) موجودة بدون استخدام فعلي.
5. **مثال عملي:** في صفحة استلام المرتجعات `DoneRequest.jsx` على شاشة الكمبيوتر (1366px)، أزرار الفلترة الصغيرة (`All`، `Checked`، `Unchecked`) واخدة كلاس `btn`، فـ `theme.css` فرضت عليها `width: 100%` وخلّت كل زر ياخد سطر كامل بعرض الصفحة تحت بعض بدل ما يبقوا جنب بعض بشكل مرتب! وكمان كلاسات زي `py-4` و`px-4` و`text-white` بتتكسر بسبب Bootstrap.
6. **ليه لازم نصلحها؟** أي مبرمج هيضيف زر أو كارت جديد بـ Tailwind هيتفاجأ إن شكله باظ ومش عارف السبب، وكمان تحميل Bootstrap كاملة بيزود حجم ملفات الـ CSS بحوالي `251 KB` بدون داعي.
7. **الحل المقترح:** حذف `@tailwindcss/vite` غير المستخدمة، وإلغاء القاعدة العامة `.btn { width: 100% }` من `theme.css`، وتحويل الصفحات اللي لسه بتستخدم كلاسات Bootstrap (مثل `CategoryPage` و`DoneRequest` و`UsersPage`) إلى Tailwind بالكامل عشان نقدر نشيل Bootstrap تمامًا.
8. **الأولوية:** متوسطة (المرحلة 3 — بعد حل المشاكل الحرجة ومشاكل الموبايل).

#### `AUDIT-041` — اختلاف أشكال الكروت وعدم تساوي ارتفاعاتها وقص الصور

1. **اسم المشكلة:** وجود 3 تصميمات مختلفة تمامًا لكروت المنتجات مع تفاوت ارتفاع الكروت وأحجام الصور.
2. **درجة الخطورة:** متوسطة (Medium).
3. **المكان:** `resources/js/Components/Card.jsx`، `CategoryProductCard.jsx`، `CartCard.jsx`، `CategoryCard.jsx`، و`OsraPage.jsx`.
4. **إيه المشكلة؟** الصفحة الرئيسية `/home` بتعرض المنتج بكارت Tailwind بأزرار تدرج برتقالي/أزرق (`Card.jsx`)، وصفحة الفئة `/categories/10` بتعرض نفس المنتج بكارت Bootstrap مختلف تمامًا (`CategoryProductCard.jsx`)، وصفحة السلة `/cart` بتعرضه بشكل ثالث (`CartCard.jsx`). ده غير إن الكروت مش واخدة `Flexbox Column` بارتفاع موحد (`h-full flex flex-col`) ونسبة أبعاد موحدة للصور (`Aspect Ratio` يعني نسبة الطول للعرض).

7. **الحل المقترح:** توحيد الكارت في مكون واحد (`ProductCard`) مبني بـ Tailwind، وتثبيت حاوية الصورة بنسبة `aspect-[4/3]` مع `object-cover`، واستخدام `h-full flex flex-col` مع `mt-auto` على الأزرار عشان كل الأزرار في نفس الصف تكون على خط واحد.
8. **الأولوية:** متوسطة (المرحلة 3).

7. **الحل المقترح:** بناء مكوّن `<AppLayout>` يضم `<NavBar>` و`<main>` و`<Footer>` موحدين في كل الصفحات، وإضافة شريط `Breadcrumbs` في صفحات الفئات والمنتجات، وتقليل ارتفاع الـ `Hero` وإبراز زر `Learn More`.
8. **الأولوية:** متوسطة (المرحلة 3).

   3. استبدال `.row` / `.col-6` في `CategoryPage` بشبكة Tailwind `grid`، وإضافة `overflow-x: clip` كشبكة أمان مدروسة بعد إزالة العناصر الخارجة (مع تجنب `overflow-x: hidden` اللي بيكسر `position: sticky` بتاع الـ NavBar!).
